# Wrecking Crew-like 仕様書(AI引き継ぎ用)

このファイルは「ゲームを全く知らない新規チャット」が context.txt だけで開発を続けられるようにするための、
**設計と確定仕様の一次資料**。コードと食い違ったらコードが正で、このファイルを直すこと。

## 0. これは何か
ファミコンの「レッキングクルー」風の2Dパズルアクション(ブラウザ、ビルド不要、依存なし、`index.html` を開くだけで動く)。
ハンマーで壁・壊せる梯子を全部壊すとクリア。敵に触れるとミス(残機-1)。ステージエディタ(スマホ対応・タッチ操作あり)付き。
所有者は日本語話者で、仕様を口語・短文で伝えてくる。曖昧な指示が多いので、**解釈が割れた所は解釈を明記して実装し、返答で一言確認する**。

## 1. 作業ルール(AIへ)
- 返答は日本語。結論と「何をどう直したか」を先に、短く。専門用語を並べない。
- コードの作法: グローバル名前空間 `window.WC` のみ。ES modules / ビルド / 外部ライブラリは使わない。
  既存の圧縮気味の書き方(1〜2文字の変数、1行に詰める)に合わせる。コメントは日本語で「なぜ」を書く。
- 新しい `js/` ファイルを足したら **`index.html` の `<script>` に登録**する(読み込み順が依存順。第2章参照)。
- 変更したら `npm test`(依存なし)を通す。ブラウザ確認が必要なら `npm run test:e2e`(playwright が要る)。
  仕様を変えたらテストも更新する。見た目やプレイ感は実機で確認できないので、断定せず「確認できていない」と言う。
- 仕様を変えたら **この SPEC.md を更新**し、最後に `npm run context` で context.txt を作り直す。
- 納品は動く状態のプロジェクト一式を zip(フォルダ名 `rekikuru-main`)で返す。**zip の作り直し・添付忘れに注意**(過去にやらかした)。
  コード実行環境が無い場合は、変更したファイルを全文で出す(差分ではなく)。

## 3. 座標・地面・移動のモデル(最重要)
- 1マス=32px(`CONFIG.tile`)。座標は (x,y)、y は下向き。ステージ=文字列の行の配列。幅 w=最長行(短い行は空白で埋める)。
- 1マスに置けるオブジェクトは1つ(`Level.objs` は `"x,y"`→オブジェクトの Map)。
- **キャラはマス(x,y)の「底の線」に足が着く**。つまり床の線は「そのマスの下端」に描く(`Gfx.fns.floor`)。
  キャラが歩く段(床の段)と、その上の「空中の段」(梯子の途中)が交互に並ぶ。梯子の上下端は床の段にある。
- **地面(`Level.floor[y][x]`)はオブジェクトとは別レイヤー**。オブジェクトが壊れても地面は残る。作られ方(`Level` コンストラクタ):
  - 空白以外の文字は地面を持つ('=' だけでなく壁・ドラム缶・鉄柱・爆弾・扉・P・敵の文字も)。
  - 梯子(L/H)自体には自動で地面を作らない。梯子の先端に接続する足場は、エディタで `=` などの足場を明示的に置く。梯子の横のマスから、その一つ上に実在する足場へは一段上がれる。
  - 鉄柱 I の **真上** にある O/W/w/V は自前の地面を持たない(鉄柱ごと宙に載っている)。
  - **左右端の列(x=0 と x=w-1)は全段が地面。消せない**(その文字が空白でも)。
- `Level.standable(x,y,bg)` = 最下段 || 地面 || 梯子 || (bg以外で)真下が通行止めオブジェクト(ドラム缶の上に立てる)。梯子列の上端・下端の地面は残るが、連結部には中間の足場を作らない。
  立てないマスにいるキャラは毎ステップ1マス落ちる(速い)。
- 移動 `Level.canStep(x,y,dx,dy,bg)`:
  - 縦は移動先に梯子が必須。横は自由(端はループ)。
  - bg=false のキャラは `blocks` なオブジェクト(ドラム缶)に入れない。bg=true(裏側の敵=foreman)は無視。
  - **段差**: ドラム缶の上(`onDrum`)にいると、横の「普通の床のマス(`ground`=地面があり梯子ではない)」へは上がれない。
    降りる(空中へ出て落ちる)のは可。梯子マスへは移れる。
- **左右ループ**: `tx` は折り返した後のマス、`rx` は端の外(-1〜w)まで連続して動く(`Actor.sync`)。
  描画は `Actor.draw` が反対側にも半身を描く(火の玉は `nowrap` でループしない)。キャラ間の距離は `Game.near` が折り返しを考慮。
- キャラの `x,y`=いるマス(移動中は出発マス、到着で更新)、`rx,ry`=描画/当たり用の連続座標、`t`=移動の進行 0→1。

## 4. ステージ文字(エディタのパレット=`WC.TOOLS`)
`=`床 / `W`壁1 `w`壁2 `V`壁3(HP=CONFIG.wall.hp) / `L`壊せる梯子(クリア条件) `H`壊せない梯子 / `O`ドラム缶 / `I`鉄柱 / `B`爆弾 / `D`扉 /
`P`プレイヤー(1つだけ) / `1`追尾 `2`直進 `3`親方(裏側) `4`高速追尾 / ` `消す。
クリア条件 = `needsBreak` なオブジェクト(壁・L梯子)が0個。

## 5. オブジェクトと敵の挙動
- **壁**: 背景オブジェクト(通行を妨げない)。立っているマスで叩くと HP-1。爆風でも -1。
- **梯子 L**: 叩く/爆風で壊れ、上下の L に連鎖して壊れる(`breakInterval`)。掴まっていた敵は異常落下、プレイヤーはその場から真下へ落ちる。H は壊れない。
- **ドラム缶 O**: 常に通行止めの1マス障害物。上から落ちてきたキャラはめり込まず上に立つ。
- **鉄柱 I**: 背景。爆風では破壊可能(クリア条件のカウント対象ではない)。ハンマーで叩くと、真上にドラム缶/壁が載っている場合は載っていた物を `fallDelay` 秒後に落とし、鉄柱自体は壁と同様に消える(地面は残る)。載っていた物がない場合も鉄柱自体は消える。載っていた物が `fallDelay` 秒後に
  「鉄柱が立っていた地面」まで落ちてそのマスに残る(1つ下の段ではない)。
  落ちるドラム缶: 同じ列のプレイヤーは死亡、敵は撃破。落ちる壁: 無害・落下中は壊せない。着地先に別オブジェクトがあれば割れて消える。
- **ドラム缶の上の「詰み」は仕様**: ドラム缶の天面は床より少し低い。穴(足場に挟まれたドラム缶の上)に降りると左右の足場へ上がれず出られない
  (梯子が隣にあるか、片側が空いていれば出られる)。敵も同じ。詰んだら敵に倒されるのを待つだけで、救済処理は無い(意図通り)。
- **爆弾 B**: 叩くと導火線 `fuse` 秒後に起爆、そのマスのキャラは異常落下(叩いた本人は方向入力で逃げれば免れる)。
  上下左右の隣接物に通常の爆風を適用する。横方向は、隣の破壊可能な物が爆風一回分で消えた場合、その隣の破壊可能な物へ連鎖し、破壊ごとに `0.2` 秒待つ。消えなかった場合や破壊不能物に当たった場合は連鎖を止める。壁・L梯子・鉄柱は破壊可能。扉を開け、隣の爆弾に連鎖(`chainDelay`)。鉄柱はクリア条件のカウント対象ではない。
- **扉 D**: 叩くと `openTime` 秒開く。開いた扉に着いた敵(noDoor でない)は隠れる。全敵が隠れると強制的に扉が開き、敵が出てくる(`checkAllHidden`/`onExit`)。
- **異常落下(`startAbn`)**: 床を無視して最下段まで速く落ちる(ドラム缶の上で止まる)→着いたら `fall.stun` 秒気絶し、速度 `fall.boost`×lv アップ(lv最大2)。プレイヤーは落下中ハンマー不可。
- **追尾 1/4**: BFS(`Level.step`)で落下込みの最短経路。4は高速。**直進 2**: プレイヤー無視で一方向、梯子があれば1マス上り次は横へ、障害物で反転。
- **親方 3(裏側の敵)**: 壁・ドラム缶を無視(bg)して追尾。同じマスに来ると `windup` 秒後に殴る → **プレイヤーは異常落下するだけでミスにはならない**
  (落下中・気絶中は殴られない)。触れても無害(harmless)。プレイヤーがハンマーで殴ると親方が異常落下。ときどきサボる(`lazy`)。
- **火の玉**: `Game` が `interval` 秒ごとに、左右端のどちらかから、**横幅の半分以上が地面の段(と最下段)**のランダムな1段に出し、反対端まで直進(ループしない)。触れるとミス。
- ミス: 追尾/直進/火の玉に触れる(`near<.65`)、落ちるドラム缶の下。残機 `player.lives`=3、0でゲームオーバー。

## 6. ゲーム進行(`WC.Game`)
- 状態 `ready`(1.5秒)→`play`→`dead`(1.2秒後に同ステージをやり直し or `over`)/`clear`(2秒後)。
- `later(秒,fn)` が唯一のタイマー。`load()` で `timers` を捨てて `epoch++`(古い予約が残らない)。`update` はタイマー実行中に epoch が変わったら即 return。
- `onOver` / `onClear` は main.js が設定。テスト中(エディタの「テスト」)はクリアでエディタへ戻る。通常プレイはクリアで同じステージを最初から(残機は引き継ぎ)。
- **重要**: `onOver/onClear` は `Game.update` の中で呼ばれ、main.js の `setMode` が `G=null` にする。メインループは `update` の後に `G` を再確認してから描画し、
  `requestAnimationFrame` を最初に予約する(ここを崩すと「2回目のプレイで画面が真っ暗」になる。過去のバグ)。

## 7. 調整値 `WC.CONFIG`(config.js)
`player{speed,hammerTime,lives}` `wall{hp,colors}` `door{openTime,stunAll,minHide,safe}` `drum{fallDelay,fallSpeed}`(壁の落下にも使う)
`bomb{fuse,chainDelay}` `ladder{breakInterval}` `fall{speed,stun,boost}` `enemies{chaser,fastchaser,runner,foreman,fireball{speed,interval,...}}`。
数値は設定画面にスライダーで自動表示される(`params.js`)。新しい数値を足せば自動で出る。`WC.DEFAULTS` は初期値のコピー。保存は localStorage キー `wc1`。

## 8. 拡張ポイント
- 見た目: `WC.Gfx.set('chaser',(c,x,y,s,self)=>c.drawImage(...))`。種類名= `drum iron wall ladder door floor player chaser runner foreman fastchaser fireball bomb`。
- 音: `WC.Sound.files.hit='hit.wav'`。イベント名= hit wall ladder bomb door drumHit drumLand fall die clear。
- 新しいオブジェクト: `WC.Objects['文字']=class extends WC.Obj`(`update(dt,g)` `onHit(g,by)` `onBlast(g)` `blocks` `needsBreak`)+ `WC.TOOLS` に追加。
- 新しい敵: `WC.Enemies['数字']=class extends WC.Enemy`(`decide(g)`→`[dx,dy]|null`)+ `WC.CONFIG.enemies` に値 + `WC.SPR`/`WC.TOOLS`。

## 9. 経緯と確定済みの判断(所有者の指示と、そこでの解釈)
- ドラム缶に「オブジェクトとしての判定」を → 横から入れないだけでなく、落下・異常落下でもめり込ませない(上に立つ)。
- 「ドラム缶は低いので足場の横にあると出られず詰む、を仕様に」→ 第3章の段差ルール。
- 梯子・鉄が地面と同化していた(梯子を壊すと床が消えた)→ 地面を別レイヤーに。
- 鉄柱を壊すとドラム缶が1つ下の段まで落ちていた → 鉄柱の地面に着地。鉄柱は壁も載せられ、壁も落ちてくる(壁を無害にしたのはAIの判断)。
- 裏側の敵に殴られたらミスではなく異常落下。
- 火が出ない件: 出現段の条件が厳しすぎた(サンプルは1段のみ)+最初の1発が10秒後。→ 段の条件を緩和。間隔は設定で変更可。
- 左右端は全段足場(消せない)。左右ループはシームレス(半身が反対側から出てくる)。
- 全消しボタンが存在しない関数を呼んでいた → 修正。

## 10. 既知の癖・未確定
- サンプルステージの8行目だけ21文字で、他は20文字(幅=21になり、右端の列は8行目以外は空白)。左右端が常に足場になったので実害は小さいが、直してはいない。
- 通常プレイでクリアすると同じステージを繰り返す(タイトルへは戻らない)。意図かどうか未確認。
- 見た目は仮(単色の四角)。左右端の足場も通常の床の線と同じ見た目。
- 最後に実機(スマホ/ブラウザ)で遊んだ確認は取れていない。ロジックはテストで確認済み。

## 11. テスト
- `npm test` … `test/logic.test.js`。ブラウザ無しで `vm` にゲームを読み込み(`test/harness.js`、乱数は固定)、ゲームロジックを検証する。
  キャラの操作は `g.keys={right:true}` で再現し、`g.update(1/60)` を回す。止めたいマスの手前でキーを離すこと(到着の瞬間に次の一歩を決めるため)。
  テストでは `g.state='play'; g.timers=[]; g.enemies=[]` で準備待ちを飛ばす。壊すものが1つも無いステージは即クリア扱いになるので壁を1つ置く。
- `npm run test:e2e` … `test/e2e.js`。playwright(+ chromium)が必要。2回目のプレイ・エディタの端・全消しを実ブラウザで確認。

WC.Level=class{
 constructor(text){
  const rows=text.replace(/\r/g,'').split('\n').filter(r=>r.length);
  this.h=rows.length;this.w=Math.max(...rows.map(r=>r.length));
  this.floor=[];this.objs=new Map();this.spawns=[];this.player={x:1,y:1};
  const at=(x,y)=>(rows[y]||'')[x]||' ',lad=c=>c=='L'||c=='H';
  rows.forEach((r,y)=>{this.floor[y]=[];for(let x=0;x<this.w;x++){
   const ch=at(x,y),O=WC.Objects[ch],E=WC.Enemies[ch];
   if(O)this.objs.set(x+','+y,new O(x,y,ch));
   if(E)this.spawns.push({E,x,y});
   if(ch=='P')this.player={x,y};
   // 地面(floor)はオブジェクトとは別レイヤー。オブジェクトが壊れても地面は残る。
   //  ・梯子は上下の端のマスだけ地面を持つ(途中のマスは持たない)
   //  ・鉄柱(I)の真上に載っているドラム缶・壁は、自前の地面を持たない(鉄柱ごと宙に浮いている)
   //  ・左右端の列は全段が足場(1マス幅)。消せない(文字が空白でも足場になる)
   // 梯子の上下端だけ床を持つ。縦に連結した梯子の途中には床を作らない。
   // 床線の描画位置(上端/下端)は Gfx.terrain 側で分ける。
   this.floor[y][x]=x==0||x==this.w-1||ch!=' '&&!lad(ch)&&!('OWwV'.includes(ch)&&at(x,y+1)=='I')}});
 }
 get(x,y){return this.objs.get(x+','+y)}
 del(x,y){this.objs.delete(x+','+y)}
 wrap(x){return(x+this.w)%this.w}
 ladder(x,y){const o=this.get(x,y);return!!(o&&o.isLadder)}
 blocked(x,y){const o=this.get(x,y);return!!(o&&o.blocks)}
 // 立てるマスか。通行止めオブジェクト(ドラム缶)の真上も足場になる(bg=背景側の敵は無視)。
 standable(x,y,bg){return y>=this.h-1||this.floor[y][x]||this.ladder(x,y)||(!bg&&this.blocked(x,y+1))||(!this.ladder(x,y)&&this.ladder(x,y+1))}
 // ドラム缶の上に立っているか。ドラム缶の天面は通常の床より少し低い。
 onDrum(x,y){return y<this.h-1&&!this.floor[y][x]&&!this.ladder(x,y)&&this.blocked(x,y+1)}
 // 梯子ではない普通の足場(床)のマスか
 ground(x,y){return(y>=this.h-1||this.floor[y][x])&&!this.ladder(x,y)}
 // 火の玉が飛ぶ段: 横幅の半分以上が地面の段と最下段
 fireRows(){const r=[];for(let y=0;y<this.h;y++)if(y==this.h-1||this.floor[y].filter(Boolean).length*2>=this.w)r.push(y);return r}
 canStep(x,y,dx,dy,bg){
  const nx=this.wrap(x+dx),ny=y+dy;
  if(ny<0||ny>=this.h)return false;
  if(!bg&&this.blocked(nx,ny))return false;
  // 梯子の先端の一つ上では、横の足場へ移るのは許可する。
  // 現在地にも移動先にも足場がなければ、空中へ横移動できない。
  if(dx&&!this.ladder(x,y)&&this.ladder(x,y+1)&&!this.ground(x,y)&&!this.ground(nx,y)&&(!bg?!this.blocked(x,y+1):true))return false;
  if(dx&&!bg&&this.onDrum(x,y)&&this.ground(nx,ny))return false; // ドラム缶の上から隣の足場へは上がれない
  // 梯子の最上段から、その一つ上のマスへ登ることを許可する。
  if(dy<0&&this.ladder(x,y)&&ny>=0&&!this.ladder(x,ny))return true;
  // 梯子の最上段の横にいる場合も、上の足場へ一段上がれる。
  // 梯子の途中から壁登りできないよう、横の梯子がこの段で終わることを確認する。
  if(dy<0&&this.ground(x,ny)&&[-1,1].some(d=>this.ladder(this.wrap(x+d),y)))return true;
  return dy?this.ladder(x,ny):true}
 dest(x,y,dx,dy,bg){ // 1歩+落下後のマス
  if(!this.canStep(x,y,dx,dy,bg))return null;
  const nx=this.wrap(x+dx);let ny=y+dy;
  if(!dy)while(ny<this.h-1&&!this.standable(nx,ny,bg))ny++;
  return[nx,ny]}
 step(sx,sy,gx,gy,bg){ // BFSで最初の一歩[dx,dy]を返す
  const seen=new Set([sx+','+sy]),q=[[sx,sy,null]];
  for(let i=0;i<q.length;i++){const[x,y,f]=q[i];
   if(x==gx&&y==gy&&f)return f;
   for(const d of[[0,-1],[0,1],[-1,0],[1,0]]){
    const n=this.dest(x,y,d[0],d[1],bg);if(!n)continue;
    const k=n[0]+','+n[1];if(seen.has(k))continue;seen.add(k);q.push([n[0],n[1],f||d])}}
  return null}
};

// 爆弾: 叩く(または連鎖)で点火→起爆。起爆時、そのマスにいるキャラは全員異常落下。
// 横方向は、破壊可能なオブジェクトを一撃ずつ連鎖破壊する。次のマスへは0.2秒待って進む。
// 上下方向の隣接オブジェクト、扉、隣の爆弾は従来どおり起爆時に処理する。
WC.Objects.B=class extends WC.Obj{
 constructor(x,y){super(x,y,'bomb');this.lit=false}
 onHit(g,by){this.light(WC.CONFIG.bomb.fuse,true)}
 onBlast(g){this.light(WC.CONFIG.bomb.chainDelay,false)}
 light(t,byPlayer){if(this.lit)return;this.lit=true;this.t=t;this.byPlayer=byPlayer;this.escaped=false}
 hitSide(g,dir){
  const L=g.level;
  let offset=1;
  const hitNext=()=>{
   const x=L.wrap(this.x+dir*offset),y=this.y,o=L.get(x,y);
   if(!o||!o.onBlast)return;
   // 連鎖先は破壊可能な物だけ。扉・爆弾などに当たったらここで止める。
   if(!(o.needsBreak||o.destructible))return;
   o.onBlast(g);
   // 今のオブジェクトが実際に消えたときだけ、その隣を0.2秒後に処理する。
   if(L.get(x,y)!==o){
    offset++;
    g.later(.2,hitNext);
   }
  };
  const x=L.wrap(this.x+dir),o=L.get(x,this.y);
  if(!o||!o.onBlast)return;
  // 爆弾に直接隣接する物には、従来どおり通常の爆風を適用する。
  if(!(o.needsBreak||o.destructible)){o.onBlast(g);return}
  o.onBlast(g);
  if(L.get(x,this.y)!==o){
   offset++;
   g.later(.2,hitNext);
  }
 }
 update(dt,g){if(!this.lit)return;
  const k=g.keys;if(this.byPlayer&&(k.left||k.right||k.up||k.down))this.escaped=true;
  this.t-=dt;if(this.t>0)return;
  const L=g.level;L.del(this.x,this.y);WC.Sound.play('bomb');
  g.actors().forEach(a=>{if(a.x==this.x&&a.y==this.y&&!(a===g.player&&this.escaped))a.startAbn()});
  // 横は左右それぞれ、破壊が成立した場合だけ0.2秒間隔で連鎖。
  this.hitSide(g,1);this.hitSide(g,-1);
  // 上下は従来どおり隣接マスにだけ作用する。
  for(const dy of[-1,1]){const o=L.get(this.x,this.y+dy);o&&o.onBlast&&o.onBlast(g)}

#!/usr/bin/env node
// npm run context → context.txt を生成する。
// 新規チャットに context.txt だけ渡せば、ゲームの仕様・構成・全ソースを把握して開発を続けられるようにするためのもの。
// 構成: ①AIへの案内 ②docs/SPEC.md(手書きの仕様書) ③ファイル一覧 ④全ファイルの中身(index.html の読み込み順)
// 依存なし(Node 標準のみ)。ソースを足しても自動で拾う。index.html に登録し忘れた js があれば警告する。
const fs=require('fs'),path=require('path');
const root=path.resolve(__dirname,'..'),OUT=path.join(root,'context.txt');
const SKIP_DIR=new Set(['node_modules','.git']),SKIP_FILE=new Set(['context.txt','package-lock.json']),EXT=new Set(['.js','.html','.css','.md','.json']);
const SPEC='docs/SPEC.md';
const M='='.repeat(5); // 区切り記号。ソース内に区切りそのものを書かない(context.txt に載せたとき本物の区切りと混ざるため)

const rel=p=>path.relative(root,p).split(path.sep).join('/');
const walk=(d,o=[])=>{for(const n of fs.readdirSync(d).sort()){const p=path.join(d,n),s=fs.statSync(p);
 if(s.isDirectory()){if(!SKIP_DIR.has(n))walk(p,o)}else if(EXT.has(path.extname(n))&&!SKIP_FILE.has(n))o.push(rel(p))}return o};
const read=f=>fs.readFileSync(path.join(root,f),'utf8').replace(/\r\n/g,'\n').replace(/\s+$/,'')+'\n';

const all=walk(root);
const html=fs.existsSync(path.join(root,'index.html'))?read('index.html'):'';
const scripts=[...html.matchAll(/<script[^>]*\ssrc="([^"]+)"/g)].map(m=>m[1]);   // 読み込み順=依存順
const warns=[];
for(const s of scripts)if(!fs.existsSync(path.join(root,s)))warns.push(`index.html が読み込む ${s} が存在しない`);
for(const f of all)if(f.startsWith('js/')&&!scripts.includes(f))warns.push(`${f} が index.html の <script> に登録されていない(動かない)`);
if(!fs.existsSync(path.join(root,SPEC)))warns.push(`${SPEC} が無い(仕様書。作ること)`);

// 並び: index.html, style.css, package.json, js(読み込み順)→その他js, test, tools, 残り。仕様書は別枠なので除く。
const rank=f=>{if(f==='index.html')return[0,0];if(f==='style.css')return[1,0];if(f==='package.json')return[2,0];
 const i=scripts.indexOf(f);if(i>=0)return[3,i];if(f.startsWith('js/'))return[4,0];if(f.startsWith('test/'))return[5,0];if(f.startsWith('tools/'))return[6,0];return[7,0]};
const files=all.filter(f=>f!==SPEC).sort((a,b)=>{const x=rank(a),y=rank(b);return x[0]-y[0]||x[1]-y[1]||a.localeCompare(b)});

const body=files.map(f=>`${M} FILE: ${f} ${M}\n${read(f)}`).join('\n');
const tree=files.map(f=>{const t=read(f);return `${f}  (${t.split('\n').length-1}行)`}).join('\n');
const spec=fs.existsSync(path.join(root,SPEC))?read(SPEC):'(docs/SPEC.md が無い)\n';
const now=new Date(Date.now()+9*3600e3).toISOString().replace('T',' ').slice(0,16)+' JST';

const guide=`【このファイルの使い方】(AIへ)
これは「Wrecking Crew-like」(ブラウザの2Dアクションゲーム)の開発引き継ぎ資料です。あなたはこの続きを開発します。
1. 第1部の仕様書を最後まで読む(設計・確定仕様・作業ルールが書いてある。ここが一次資料)。
2. 第3部の全ソースを読む。コードと仕様書が食い違ったらコードが正。直す前に必ず該当ファイルの現物を確認する。
3. ユーザーの依頼は口語で曖昧なことが多い。解釈が割れる所は解釈を明記して実装し、返答の最後に一言確認する。
4. 実行環境(Node/ブラウザ)があるなら、変更後に \`npm test\` を通し、動く一式を zip で返す。無いなら変更ファイルを全文で出す。
5. 仕様を変えたら docs/SPEC.md も更新し、ユーザーに「npm run context で context.txt を作り直してね」と伝える。
(ユーザー側: プロジェクト直下で \`npm run context\` を実行すると、このファイルが最新のソースから再生成されます)
`;

const out=`${guide}
生成: ${now} / ファイル ${files.length + 1} 個
${warns.length?'\n【警告】\n'+warns.map(w=>'- '+w).join('\n')+'\n':''}
################################################################
# 第1部: 仕様書 (${SPEC})
################################################################
${spec}

# 第2部: ファイル一覧(第3部の掲載順)
